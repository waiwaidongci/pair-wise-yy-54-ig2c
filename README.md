# 市政道路施工封路方案协调与审批平台

源提示词编号：11。支持分段封路范围、施工阶段、绕行路线、车道收窄和临时设施的同一地图协作；检查相邻工程、救护通道、公交覆盖和绕行时延冲突；提供图层开关、路线绘制、阶段时间轴、条件会签、版本比较和公开通告包导出。

## 道路修订模型（核心规则）

施工阶段、会签意见、公开通告三者绑定**同一条道路修订号（R1、R2…）**：

1. **统一锚点**：围挡、时间、绕行任一项变化都生成新修订；阶段与意见带 `baseRevision`，公开通告头部写明“依据道路修订 R*”。
2. **影响矩阵、只废受影响单位**：
   - 围挡变更 → 交通、应急重确认
   - 时间变更 → 公交、应急重确认
   - 绕行变更 → 交通、公交重确认

   其他单位意见一律沿用；锚定旧修订的意见仅在本次变更落入该单位职责时失效。失效意见**保留不覆盖**，在当前修订上重确认后产生新意见。
3. **先到占用、后到留场**：同一阶段同一修订，先提交的会签人持锁；后到者不覆盖，只保存现场文字并生成与先到者的逐字段差异。新修订后锁与留场记录随旧修订清空。
4. **原操作号重试**：每次写带操作号 `opId`；写入失败时业务草案与审计记录留在内存、不落盘，顶部横幅可按**同一操作号**重试，审计记录只更新尝试次数，绝不重复追加。可用“模拟下一次写入失败”体验。
5. **旧数据升级**：缺少修订号的旧数据自动升级为初始版本 R1（生成迁移修订与审计），全部阶段列入“未重确认”清单，公开通告中单列、不作为生效承诺。
6. **公开通告**：文件名与正文均带修订号；每条阶段/绕行标注锚定修订；未重确认阶段单列并列出待重确认单位。

代码组织：

- `src/types.ts`：修订/意见/会签锁/审计模型与 `IMPACT_MATRIX`
- `src/core/revision.ts`：纯逻辑（修订、失效、并发会签、重确认、迁移、通告）
- `src/core/transport.ts`：写入传输层（可注入失败，按操作号统计尝试次数）
- `src/store/scheme.ts`：Pinia + 写入引擎（幂等、失败重试、撤销）

## 技术栈

Vue 3、Arco Design Vue、Pinia、Vue Router、Apollo Client、GraphQL、MapLibre GL、Vite、TypeScript。

## 运行

```bash
npm install
npm run dev      # http://localhost:62054
npm test         # 90 项业务规则自检（修订/失效/并发/重试/迁移/通告）
npm run build
```

演示入口（顶栏按钮）：`载入旧数据(演示升级)` 复现旧数据 → R1 升级；`载入 R2 演示数据` 直接查看 R2 修订、先到锁、后到差异与失效重确认。
